# Storage and Scanning Contracts

## `IFileStorageService`

```text
UploadAsync(Stream content, string storageKey, string contentType) -> storage key
DeleteAsync(string storageKey) -> completion
OpenReadAsync(string storageKey) -> readable stream
ExistsAsync(string storageKey) -> boolean
```

Implement the training provider with local filesystem storage rooted outside `wwwroot`. Storage keys are generated by the application and use relative, portable segments. A future cloud provider may implement the same contract without changes to document business logic.

## `IMalwareScanner`

```text
ScanAsync(Stream quarantinedContent, string detectedContentType) -> Clean | Threat | Failed
```

The training implementation must provide a deterministic local test double supporting clean, threat, and failure outcomes. A production implementation may call a real scanner, but the document service must treat threat and failure as non-accessible results.

## Retrieval endpoint contract

Authorized download/preview handlers accept a document identifier, perform service authorization before opening storage, and return:

- `200` with the stored content type and safe display filename for downloads.
- `200` with `Content-Disposition: inline` only for validated PDF, JPEG, or PNG previews.
- Indistinguishable `404` for missing or unauthorized documents.
- No direct filesystem paths or public static-file URLs.
